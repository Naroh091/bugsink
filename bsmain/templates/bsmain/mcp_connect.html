Connect MCP clients

Connect Claude Code, OpenCode, Hermes (or any MCP-compatible client) to this Bugsink instance so an LLM can autonomously browse issues, inspect stacktraces, and investigate errors.

You need an API token to authenticate. Replace <your-token> in the commands below with a token from the Tokens page.

Claude Code

Run this once in your terminal. It writes the server into your local Claude Code config and applies only to your machine.

{% code %}:::bash claude mcp add --transport http bugsink {{ mcp_url }} \ --header "Authorization: Bearer " {% endcode %}

For team-wide setup, commit a .mcp.json at the root of your repo (this repo already has one). Each person sets BUGSINK_TOKEN in their shell and the server is picked up automatically:

{% code %}:::bash export BUGSINK_TOKEN= {% endcode %}

Add the line above to your ~/.bashrc or ~/.zshrc to make it permanent. Type /mcp in Claude Code to verify — you should see bugsink · connected.

OpenCode

Add the server under mcp in your opencode.json (project root, or globally in ~/.config/opencode/).

{% code %}:::json { "$schema": "https://opencode.ai/config.json", "mcp": { "bugsink": { "type": "remote", "url": "{{ mcp_url }}", "enabled": true, "oauth": false, "headers": { "Authorization": "Bearer {env:BUGSINK_TOKEN}" } } } } {% endcode %}

{env:BUGSINK_TOKEN} is read from your environment; oauth: false tells OpenCode to use the token instead of attempting an OAuth flow.

Hermes

Add the server under mcp_servers in your Hermes config.yaml, then run /reload-mcp (or restart Hermes).

{% code %}:::yaml mcp_servers: bugsink: url: "{{ mcp_url }}" headers: Authorization: "Bearer " {% endcode %}

Optionally, restrict the exposed tool surface with tools.include, e.g. to the read-oriented list_issues, get_issue, get_event_stacktrace.
